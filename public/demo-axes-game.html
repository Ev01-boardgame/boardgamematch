遊戲 8 軸 × 玩家 8 軸 對應（示意說明）

本頁用來說明兩件事：「每款遊戲的 8 軸怎麼來」，以及「推薦時如何把玩家 8 軸和遊戲 8 軸配對」。 目前是設計草圖，方便一起討論與修改，之後再實作到程式裡。

遊戲 8 軸：資料流示意

階段 資料來源與做法
1. 基礎值（Import）
  • 從 BGG / 其他來源抓到的資料：player count / play time / complexity / themes / mechanics。
  • 在 admin-bgg-import.html 先用簡單規則給每軸一個 baseline（例如：時間長 → 沉浸高；weight 高 → 策略高、親和低）。
  • 這些值寫進 game_database.axis_* 當作「起點」，之後會被玩家評價微調。
2. 玩家影響（Voting）
  • 玩家做完桌友適性 → 寫入 user_preference_profiles（每人一組 8 軸）。
  • 玩家在「喜歡 / 普通 / 不喜歡」中把某款遊戲加入「喜歡」→ 系統把該玩家的 8 軸視為對這款遊戲的正面樣本。
  • 可以用「加權平均」：axis_strategy(game) 逐漸往所有喜歡這款的人之平均靠近（也可只吃最近 N 位玩家）。
3. 管理員微調（Admin）
  • 在 admin-games 頁面上，管理員可以手動改一款遊戲的 8 軸（覆蓋演算法算出來的值）。
  • 也可以把某些軸鎖定不再由玩家資料自動改寫（例如經典派對遊戲的「社交」與「心機」）。

真實實作時，這三個來源會合在一起：baseline（import） + 玩家統計（喜歡它的人） + 管理員覆蓋，存回 game_database.axis_*。

推薦時：玩家 8 軸 vs. 遊戲 8 軸

軸向 配對原則（示意） 計分想法（示意）
策略 strategy 玩家「策略」高 → 優先推薦策略高的遊戲；玩家策略低 → 避免太燒腦。可搭配 complexity_bucket 做硬上限。 score += (12 - |S_player - S_game|)
若玩家策略 ≤ 3，複雜度 bucket = expert 則直接扣分
對抗 conflict 玩家不喜歡衝突 → 避開對抗高的遊戲；喜歡衝突的人則相反。 score += (12 - |C_player - C_game|)
玩家 conflict 低且遊戲 conflict 高時額外扣分
合作 coop 玩家偏好合作 → 優先推薦合作／半合作遊戲；不喜歡合作 → 優先推薦競爭型。 score += (12 - |Coop_player - Coop_game|)
社交 / 心機 social_fun / manipulation 喜歡說話、演戲、猜內鬼的人 → 推薦社交／心機高的遊戲；內向或不喜歡衝突的人 → 避免。 兩軸合併計算：平均差距越小分數越高
可搭配「今晚想不想玩唬人遊戲？」的即時條件
親和 / 沉浸 accessibility / immersion 親和高 → 優先推薦規則短、時間短；沉浸高 → 接受較長、劇本感強的遊戲。 用玩家「這次想玩多重」條件，限制可推薦的時間區間
再用 8 軸做微調
運氣 luck 喜歡骰運 / 抽牌感 → 推薦 luck 高的遊戲；喜歡完全掌控 → 避免 luck 高。 score += (12 - |Luck_player - Luck_game|)

真正實作時，可以把每一軸的「差距」轉成 0～權重的分數，累加後再加上「今晚條件題」與「遊戲基礎條件（人數、時間、年份等）」的過濾， 最後得到一個總分，作為「今晚玩什麼？」與推薦清單的排序依據。
